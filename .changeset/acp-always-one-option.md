An ACP approval card no longer picks one of several grants of the same kind for the person. `decisionsFromAcpOptions` offers an allow decision, or `deny-always`, only when the agent sent exactly one option of that kind, and `toAcpPermissionResponse` answers only with that option, cancelling the request when the agent sent several. Before, Always answered the agent's first `allow_always` option: on Claude Code's ExitPlanMode that is "Yes, clear context (26% used) and use auto mode", and on a Gemini CLI MCP tool "Allow all server tools for this session". Such a card now offers Approve and Deny, and Approve answers the agent's one `allow_once` option. Deny still answers the agent's first `reject_once` option when it sent several, since a denial grants nothing. When the agent sends one `allow_always` option, Always still answers it. To say what it grants, put that option's `name` in the card's `description` and in `labels.approvalCard.resolved['allow-always']`, and keep the button's short label: card buttons don't wrap, and a long name on Always pushes Approve and Deny off a phone-width card. When `decisionsFromAcpOptions` returns no decision, as for an agent that sent only several `allow_always` options, answer `{ outcome: { outcome: 'cancelled' } }` right away instead of rendering a card.
