`DiffReview` and `Markdown` stay responsive on large inputs. In `DiffReview`, unchanged lines shown with E or the gap's buttons render only near the screen past their first 100, as a hunk's rows do, so "Show all" in a 20,000-line file no longer adds 480,000 elements; a line over 2,000 characters, such as a minified bundle's, is plain text without syntax colors, one element instead of one per token, so a changed 1.3 MB line no longer blocks the page for seconds; and a review with more than 100 hunks renders them 100 per task, so 1,000 hunks no longer block the page for a quarter of a second at once. The gaps between hunks no longer render again on every decision, or when the component around the review renders. `Markdown` parses a streamed answer a block at a time, cut at blank lines, so a delta parses its last 1,000 or so characters again rather than the whole text; text with a link reference or footnote definition (also in a list or a quote), or a line outside fenced code starting with `<`, is still parsed whole.
